# T006: Notion 지급 요청 DB 연결을 점검하고 검증용 샘플 데이터를 입력

> Phase 0 | 관련 기능: F009 | 선행 작업: T004 | 크기: S | 상태: 대기

## 명세
- PRD "데이터 모델": 유일한 DB "지급 요청", 12개 속성. 상태는 status 타입, 옵션 4개(요청 기본 / 승인 / 지급완료 / 반려)는 Notion 화면에서 설정.
- PRD 가정: 저장소 공개 + 데모 로그인 → **실제 금액·수령처가 아닌 샘플 데이터만** 사용.
- 외부 준비 작업이라 늦어질 수 있다. Phase 1·2는 이 작업 없이 진행하고, **T051(Notion 교체) 착수 전까지만** 끝내면 된다.
- 샘플 분포는 T023 목업과 같게 맞춘다 (교체 후 같은 E2E 시나리오를 재사용하기 위해).

## 관련 파일
- 수정: `.env.local` (커밋 금지)
- 참고: `.env.example`, `src/lib/mock/payments.ts`(T023 분포)

## 착수 전 확인
- [ ] `notion-api-docs`로 data source ID 확인 방법 확인 (DB ID와 다름) `[확인 필요]`

## 구현 단계
- [ ] 1. `/notion:setup [DB ID]` 실행 — 통합(integration) 공유, data source 속성 점검 (토큰 값은 출력하지 않음)
- [ ] 2. 속성 12개 확인: 제목(title), 요청자·수령처·계좌·반려 사유·메모(rich_text), 금액(number, 원), 지급 예정일·처리일(date), 상태(status), 분류(select: 정산금·용역비·경비·기타), 증빙(url)
- [ ] 3. 상태 옵션 이름 4개가 정확히 `요청`·`승인`·`지급완료`·`반려`이고 기본값이 `요청`인지 확인
- [ ] 4. Notion MCP로 샘플 약 30건 입력 (아래 분포)
- [ ] 5. `.env.local`에 `NOTION_TOKEN`·`NOTION_DATA_SOURCE_ID` 설정, `git status`에 `.env.local`이 나타나지 않는지 확인

**샘플 분포 체크리스트**
- [ ] 상태별: 요청 10 / 승인 8 / 지급완료 7 / 반려 5 내외
- [ ] 연체(예정일 < 오늘): 요청 2건·승인 2건, 연체 날짜의 반려 1건(연체 제외 확인용)
- [ ] 지급 예정일 빈 건 2건 이상
- [ ] 이번 주 / 이번 달(이번 주 밖) / 다음 달 건 각 2건 이상
- [ ] 계좌가 마스킹 형식이 아닌 건 1건 (예: `국민 123456789012` — 실제 계좌 아님)
- [ ] 증빙: `https` 링크, `http` 링크, `javascript:alert(1)`, 빈 값 각 1건 이상
- [ ] 검색 확인용: 영문 대소문자 섞인 수령처(예: `Acme Studio`), 한글 제목
- [ ] 반려 건에 반려 사유·처리일 입력, 메모 있는 건 포함
