# 지급 요청·승인 트래커 MVP PRD

## 🎯 핵심 정보

**목적**: Notion에 흩어진 지급 요청의 승인·지급·반려 처리와 지급 일정(연체 포함)을 한 화면에서 관리한다.
**사용자**: 수익 지급·집행을 처리하는 재정 관리 담당자 (1인 또는 소수 팀).

**전제**
- 지급 요청 **등록은 Notion 화면에서만** 한다. 웹앱에는 등록 폼이 없다.
- 웹앱은 조회와 **상태 변경(승인 / 지급완료 / 반려)** 만 담당한다.
- 기존 "주문" 예제 화면은 **지급 요청 화면이 대체**한다 (주문 메뉴·페이지·목업 데이터 제거, 목록 패턴만 재사용).

**가정 / 비범위 (보안)**
- 스터디·테스트용 프로젝트이므로 저장소를 공개하고 **데모 로그인(형식만 맞으면 통과)을 그대로 유지**한다.
- 이에 따라 **배포 주소를 아는 누구나 Notion 데이터를 조회하고 상태를 변경할 수 있는 위험을 수용**한다. 실제 운영 전에는 보안 강화가 필요하며 이번 범위에서 다루지 않는다.
- 따라서 Notion에는 **실제 금액·수령처 데이터가 아닌 샘플 데이터만** 사용한다.

## 🚶 사용자 여정

```
1. 로그인 페이지 (미인증 상태로 대시보드 계열 접근 시 자동 이동, 원래 페이지 정보 유지)
   ↓ 로그인 성공 (데모 인증)
2. 대시보드 페이지 (요약 확인)
   ↓ 카드 클릭 → 아래 표의 조건이 적용된 목록으로 이동
3. 지급 요청 목록 페이지 (검색·상태 필터·연체만·페이지)
   ↓ 행 클릭
4. 지급 요청 상세 페이지 (증빙 확인)
   ↓ 현재 상태 확인
   [요청]   → 승인 / 반려(사유 입력 필수)
   [승인]   → 지급완료 / 반려(사유 입력 필수)
   [지급완료·반려] → 변경 버튼 없음 (읽기 전용)
   ↓ 처리 성공 (Notion 갱신, 처리일 기록)
5. 상세 페이지 즉시 갱신 표시. 목록·대시보드는 캐시가 즉시 만료되어 다음 조회 때 최신 값 표시
   (Notion에서 직접 고친 내용은 최대 60초 늦게 반영, 수동 새로고침 버튼으로 즉시 확인)

- 로그인 상태로 로그인/회원가입 페이지 접근 → 대시보드 페이지로 이동
- 없는 지급 요청 또는 Notion 조회 실패 → 상세 페이지 안에서 오류 안내 + 목록으로 돌아가기
```

**대시보드 카드 → 목록 조건**

| 카드 | 이동 시 목록 조건 |
|------|------------------|
| 요청 건수 | 상태 = 요청 |
| 승인 건수 | 상태 = 승인 |
| 지급완료 건수 | 상태 = 지급완료 |
| 반려 건수 | 상태 = 반려 |
| 연체 | 연체만 켜짐, 상태 = 전체 |
| 이번 주 / 이번 달 금액 | 표시 전용 (이동 없음) |

- "연체만"은 요청·승인 상태의 건만 남기므로, 상태 필터가 지급완료·반려일 때 함께 켜면 결과는 빈 목록이다.

**상태 전이 규칙**

| 현재 상태 | 가능한 처리 | 비고 |
|-----------|------------|------|
| 요청 | 승인, 반려 | 반려 시 사유 필수 |
| 승인 | 지급완료, 반려 | 지급 전 취소를 위해 승인 후 반려 허용, 사유 필수 |
| 지급완료 | 없음 | 최종 상태. 정정은 Notion에서 직접 수정 |
| 반려 | 없음 | 최종 상태. 재요청은 Notion에서 새 요청으로 등록 |
| 알 수 없음 (옵션 이름 불일치) | 없음 | "알 수 없음" 배지, 처리 버튼 숨김 |

- 허용되지 않은 전이(예: 요청 → 지급완료)는 서버에서도 거부한다. 화면 버튼 숨김만으로 막지 않는다.
- 처리일은 **마지막 상태 변경 시점의 오늘 날짜(KST, 날짜만)** 로 기록한다 (승인일은 별도 보존하지 않음).

## ⚡ 기능 명세

### 1. MVP 핵심 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F001** | 지급 요청 목록 조회 | 제목·수령처·요청자 검색, 상태 필터, **연체만 필터(툴바 토글)**, 페이지 이동. 조건은 URL과 동기화. 서버가 Notion 전체를 조회(100건 단위 커서 반복)한 뒤 검색·필터·정렬·페이징을 수행하고 `{ items, total, page, pageSize }` 형태로 반환. 검색은 NFC 정규화 + 대소문자 무시 부분 일치. 정렬은 지급 예정일 오름차순, **예정일이 빈 건은 맨 뒤**. 데이터 규모 전제: 수천 건 이하, 상한 10,000건 | 처리할 건을 찾는 기본 동선 | 지급 요청 목록 페이지 |
| **F002** | 지급 요청 상세 보기 | 전체 속성, 증빙 링크, 반려 사유, 처리일, 메모 표시. 증빙은 http/https 주소만 링크로 표시하고 그 외는 "유효하지 않은 링크"로 표시 | 승인 전 근거 확인 | 지급 요청 상세 페이지 |
| **F003** | 상태 변경 | 전이 규칙에 따라 승인 / 지급완료 / 반려 처리 후 Notion 상태 갱신, 처리 전 확인창. **동시성**: 처리 직전 서버가 건을 재조회해 전이 규칙을 검사하고, 클라이언트가 보낸 `last_edited_time`과 다르면 409 "다른 곳에서 수정됨"으로 거부. 처리 중 버튼 비활성화. 재조회~쓰기 사이의 남은 경합 위험은 수용 | 웹앱의 핵심 가치 | 지급 요청 상세 페이지 |
| **F004** | 반려 사유·처리일 기록 | 반려 시 사유 필수(trim 후 1~2000자), 모든 처리 시 처리일(KST 날짜만) 자동 기록 | 처리 이력 추적 | 지급 요청 상세 페이지 |
| **F005** | 지급 예정 금액 요약 | 이번 주(월~일)·이번 달 지급 예정 금액 합계 (상태가 요청·승인인 건 기준). 기본값(변경 가능): 이번 주/달 범위에 속한 미지급 건은 오늘보다 앞선 날짜(연체)여도 합계에 포함하며, 연체 카드에도 함께 집계되므로 **두 카드 사이에 중복 집계**가 있다. 지급 예정일이 빈 건은 합계에서 제외 | 자금 계획 파악 | 대시보드 페이지 |
| **F006** | 상태별 건수 | 요청·승인·지급완료·반려 건수 카드 (카드 클릭 시 해당 조건 목록으로 이동) | 처리 현황 파악 | 대시보드 페이지 |
| **F007** | 연체 강조 | 지급 예정일 < 오늘이고 상태가 요청·승인인 건을 건수·금액으로 강조, 목록/상세에 연체 배지. 반려 건은 지급 대상이 아니므로 제외(사용자 확인 완료). 지급 예정일이 빈 건은 연체에서 제외(기본값, 변경 가능). 목록의 "연체만" 필터와 같은 판단 규칙을 쓴다 | 지급 누락 방지 | 대시보드 페이지, 지급 요청 목록 페이지, 지급 요청 상세 페이지 |
| **F008** | 민감정보 마스킹 | Notion에는 마스킹 값만 저장(예: 국민 ***-1234). 서버 변환 단계에서 마스킹 형식이 아닌 값은 원문 대신 가림 처리하고 경고 플래그를 전달. **목록 응답에는 계좌 필드를 포함하지 않고** 상세 응답에만 마스킹된 값을 포함 | 계좌 정보 유출 방지 | 지급 요청 상세 페이지 |
| **F009** | Notion 데이터 연동·캐시 | Notion 데이터베이스를 원본으로 읽고 상태·반려 사유·처리일을 씀. 토큰은 서버 전용. 아래 "캐시·반영 정책" 적용 | CMS 저장소 | 대시보드 페이지, 지급 요청 목록 페이지, 지급 요청 상세 페이지 |

**날짜 규칙 (F005·F007 공통)**: 오늘·이번 주·이번 달·연체 판단은 모두 **서버에서 KST 기준 `YYYY-MM-DD`** 로 처리한다 (운영 서버가 UTC여도 어긋나지 않게).

**캐시·반영 정책 (F009)**

| 대상 | 정책 |
|------|------|
| 목록·집계 | 태그 캐시 60초 |
| 상태 변경 성공 시 | 해당 태그 즉시 만료 + 클라이언트 쿼리 무효화 |
| 상세 | 캐시하지 않음 (항상 최신 조회) |
| Notion에서 직접 수정한 내용 | 최대 60초 늦게 반영. 목록·대시보드의 **새로고침 버튼**으로 수동 갱신 |

### 3. MVP 이후 기능 (제외)

- 보안 강화(허용 이메일·공유 비밀번호·쓰기 스위치·parent 검증 등): 스터디용 데모 로그인 유지, 운영 전 필요
- 웹앱 내 지급 요청 등록·수정 폼: Notion 입력으로 확정
- 승인일/지급일 별도 이력, 변경 이력 로그: 처리일 1개로 단순화
- 알림(이메일·슬랙), 다중 사용자 권한(요청자/승인자 분리): 데모 인증 한계
- 금액 합계 엑셀 내보내기, 분류별 통계 차트
- 목록 내 일괄 승인
- 지급완료·반려 건의 상태 되돌리기
- 예제 페이지와 FAQ 등 스타터킷 마케팅 메뉴: 변경 없이 유지하되 MVP 범위 밖

## 📱 메뉴 구조

```
📱 공개 메뉴
├── 🏠 홈 — F013
└── 👤 로그인 / 회원가입 — F010

🔐 로그인 후 메뉴 (대시보드 사이드바)
├── 📊 대시보드 — F005, F006, F007, F009, F011
├── 💸 지급 요청 (기존 "주문" 메뉴 대체) — F001, F002, F003, F004, F007, F008, F009, F011
├── ⚙️ 설정 — F012, F011
└── 🚪 로그아웃 — F010
```

- 지급 요청 상세 페이지는 별도 메뉴 없이 지급 요청 목록 페이지의 행 선택으로만 진입한다.
- 기존 상단 메뉴의 기능·예제·FAQ는 스타터킷 그대로 두며 MVP 범위에서 다루지 않는다.

## 🗄️ 데이터 모델 (Notion 데이터베이스)

### 지급 요청 (유일한 데이터베이스)

> 속성이 12개로 가이드(3~7개)를 초과한다. 사용자가 확정한 항목이며 관계(relation)는 없다. 샘플 데이터만 입력한다.

| 속성 | Notion 타입 | 설명 |
|------|------------|------|
| 제목 | title | 지급 건 이름. 검색 대상 |
| 요청자 | rich_text | 요청한 사람 이름. 검색 대상 |
| 수령처 | rich_text | 지급 받는 곳. 검색 대상 |
| 계좌 | rich_text | **마스킹 값만 저장** (예: 국민 ***-1234). 원문 계좌번호 입력 금지 |
| 금액 | number | 원 단위 정수. 요약 합계 계산 대상 |
| 지급 예정일 | date | 주/월 합계·연체 판단 기준 (KST 날짜). 빈 값 허용(합계·연체 제외, 목록 맨 뒤) |
| 상태 | status | 요청(기본) / 승인 / 지급완료 / 반려. 웹앱이 변경하는 유일한 상태 값 |
| 분류 | select | 정산금 / 용역비 / 경비 / 기타 |
| 증빙 | url | 증빙 문서 링크 |
| 반려 사유 | rich_text | 반려 시 웹앱이 기록 |
| 처리일 | date | 마지막 상태 변경일(날짜만, KST). 웹앱이 기록 |
| 메모 | rich_text | 자유 메모 (Notion에서 입력) |

**타입 선택·설정**
- 상태: **status 타입으로 확정**. 옵션 이름 4개(요청 / 승인 / 지급완료 / 반려)와 기본값 "요청"은 **Notion 화면에서 설정**한다. 위 4개와 다른 값이 들어오면 "알 수 없음" 배지로 표시하고 처리 버튼을 숨긴다.
- 증빙: files는 Notion 업로드 파일 URL이 약 1시간 후 만료되므로 영구 링크가 되는 url을 선택한다.
- 금액: number(원 포맷). 합계는 서버에서 계산한다.
- 계좌: 마스킹 문자열만 다루므로 rich_text.

**결정 사항 (prd-validator 검증 결과 반영)**
1. 상태는 status 타입 확정, 옵션은 Notion에서 설정, 불일치는 "알 수 없음" 처리
2. 페이지 번호 방식은 전체 조회 후 서버 페이징으로 확정 (F001)
3. 검색은 or 필터 대신 서버 측 NFC 정규화 부분 일치로 확정 (F001)
4. 집계는 전체 조회 후 서버 계산, 캐시·반영 시점은 "캐시·반영 정책"으로 확정 (F005, F009)
5. 동시 수정은 재조회 + `last_edited_time` 비교로 대응, 남은 경합 위험 수용 (F003)
6. 연체에서 반려 제외: 사용자 확인 완료 (F007)
7. 보안 강화는 비범위로 확정 (핵심 정보의 가정 참고)

**미확인 항목**
- Next 16.3.8 로컬 문서(`npm install` 후 `node_modules/next/dist/docs/`)로 캐시 API(태그 캐시·즉시 만료) 재확인
